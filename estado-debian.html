📌 Versão do Debian

Verificação de compatibilidade

O DAP é desenvolvido e testado no Debian 13 (Trixie). Se você está numa versão diferente, alguns comandos podem se comportar de forma inesperada (pacotes renomeados, repositórios alterados, sintaxe nova). Esta verificação avisa quando isso acontece.

ℹ️ Versões suportadas: Debian 13 (Trixie) e mais recentes. Versões mais antigas (12 Bookworm e anteriores) podem exigir ajustes manuais. O DAP continua funcionando, mas você pode precisar adaptar algum comando específico.
🧊 Variante do Debian (Stable/Testing/Sid)

Detecção de variante e derivados

O Debian tem três canais principais: Stable (recomendado para uso geral), Testing (pré-lançamento) e Sid/Unstable (desenvolvimento). Também existem distribuições derivadas (MX Linux, LMDE, Kali, Raspberry Pi OS). O DAP foi desenvolvido para Debian Stable puro.

ℹ️ Por que isso importa: o DAP instala pacotes que estão em repositórios estáveis. Se você está em Testing/Sid, alguns pacotes podem não existir ou ter nomes diferentes. Esta detecção avisa antes de você tentar algo que não vai funcionar.
🛡️ AppArmor
O AppArmor é o sistema de controle de acesso obrigatório padrão do Debian. Ele restringe o que cada programa pode fazer com base em perfis por aplicação — mais simples que o SELinux do Fedora e ativado por padrão desde o Debian 10.

📊 Status Atual

Mostra o estado atual do AppArmor (enabled/disabled) e quantos perfis estão carregados.

ℹ️ O que o AppArmor faz:
  • Ativo — perfis carregados e bloqueando acessos fora do permitido. É o padrão do Debian e o recomendado.
  • Inativo — nenhum perfil carregado. Reduz a segurança do sistema. Investigue antes de ativar.

⚠️ Sobre desabilitar o AppArmor

Muitos tutoriais na internet recomendam desabilitar o AppArmor quando algo não funciona. Isso não é uma boa prática no Debian — o sistema é projetado para funcionar com ele ativo, e desabilitar mascara problemas em vez de resolvê-los.

Antes de pensar em desabilitar, tente:
1. Verificar o log do AppArmor (journalctl -k | grep -i apparmor) para identificar qual perfil está bloqueando.
2. Ler a mensagem de negação — o AppArmor registra o comando exato e o caminho que foi bloqueado.
3. Se for um caso específico, criar um perfil em modo complain (só registra, não bloqueia) com aa-complain /caminho/do/programa.
4. Só como último recurso, desabilitar temporariamente com sudo aa-teardown (até o próximo boot).
ℹ️ Se precisar desabilitar permanentemente: edite /etc/default/grub e adicione apparmor=0 à linha GRUB_CMDLINE_LINUX_DEFAULT, depois rode sudo update-grub. O DAP não faz isso automaticamente — é uma decisão sua.
